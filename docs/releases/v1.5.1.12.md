# CrossDiTo 1.5.1.12（日本語版 jp.12）

CrossDiTo_jp は [CrossDiTo 1.5.1](https://github.com/dito94/CrossDiTo) に日本語の読書環境を足した個人用のフォークです。CrossDiTo 1.5.1 そのものが [CrossInk 1.5.0](https://github.com/uxjulia/CrossInk) から作られた Xteink X4 Pro 向けのテストビルドで、さらにその元は [CrossPoint Reader](https://github.com/crosspoint-reader/crosspoint-reader) です。基盤のファームウェアと、そこから受け継いだ機能の功績はすべて上流の貢献者にあります。以下に挙げるのは、CrossDiTo 1.5.1 の上に足した変更だけです。

## 1.5.1.11 からの変更

### 起動しなくなっていたのを直しました

1.5.1.10 と 1.5.1.11 は実機でブートループに入り、起動しませんでした。原因は**コードの中身ではなく、`.flash.text`（命令領域）の大きさがたまたま 64KB 境界の直前に着地したこと**です。

ESP32-S3 では flash の rodata と PSRAM が同じアドレス領域を使うため、ESP-IDF のリンカスクリプトは rodata の開始位置を「`.flash.text` のぶんだけ空ける」形で決めています。ところがその領域の原点は 64KB 境界から 0x20 ずれており、**`.flash.text` が境界の直前 0x20 バイトに着地すると、空ける量が 1 ページ足りなくなります。** 命令領域とデータ領域は MMU のページを分け合うので、データ側の割り当てがずれ、起動直後にイメージヘッダを読む処理が「ヘッダが不正」と判断して停止します。

```
E (941) cpu_start: Invalid app image header
abort() was called at PC 0x4217ed40 on core 0
Rebooting...        （以下、延々と繰り返し）
```

リンクもビルドも成功するため、**焼いてみるまで分かりません。**

| 版 | 命令領域の大きさ | 必要/確保 | 余裕 | 結果 |
|---|---|---|---|---|
| 1.5.1.9 | `0x24FBB4` | 37 / 37 ページ | +1,068 B | 起動する |
| 1.5.1.10 | `0x250060` | 38 / 37 ページ | **-128 B** | 起動しない |
| 1.5.1.11 | `0x250008` | 38 / 37 ページ | **-40 B** | 起動しない |
| **1.5.1.12** | `0x25012C` | 38 / 38 ページ | **+65,204 B** | 起動する |

1.5.1.9 は余裕 1KB しか無いところを通っていて、スリープ画面の追加（約 1.1KB）でちょうど踏み抜いた形です。機能そのものは無関係でした。

**直したこと**

1. **ビルドで弾くようにしました。** 命令領域が必要とするページ数と、確保されているページ数を突き合わせ、足りなければビルドを失敗させます。CI とリリースの両方に入れたので、**起動しないものはもう配布できません。**
2. **境界から外しました。** 命令領域に 256 バイトの詰め物を入れて境界を越えさせています。越えると空ける量は次のページまで取られるので、余裕が一気に広がります。

### 1.5.1.11 の変更について

1.5.1.11 は「OTA 中に描画タスクのスタックが溢れた」という診断で出しましたが、**これは古いコアダンプを読んだ誤りでした。** 実際に起きていたのは 1.5.1.10 の初回起動が上の abort で失敗していたことで、スタック溢れは発生していません。

描画タスクのスタックを 16KB に固定する変更そのものは安全側なので残していますが、根拠が無かったことをここに記しておきます。

### 1.5.1.10 の内容について

スリープ画面の操作一覧は、この版にも入っています。1.5.1.10 が起動しなかったのは上記のとおり大きさの問題で、機能とは無関係でした。

## 確認の状況

**実機での確認はまだです。** ビルド時の検査は通っています（余裕 65,204 バイト）。

## 既知の制限

- **小文字主体の欧文が、列の中でわずかに左へ寄って見えます。** 大文字とベースラインを揃えた結果で、小文字はインクがベースライン寄りに偏るためです。横組みで小文字が行の下側に寄るのと同じ現象です。数字と大文字は中心に来ます
- 全角形のうち `／＼｜＊＋` は縦組みで立ったままです
- 画像や表を含む本は縦組みで崩れます。組版を「幅と高さを入れ替えた紙面」で行っているためで、受け入れた判断です
- バイオニックリーディングは縦組みでは無効です。太字にする範囲を語頭から43%で決める仕組みで、分かち書きをしない日本語では前提が成り立ちません
- 背景反転は縦組みでも出ませんが、これは横組みでも同じです
- 脚注プレビューや抜き書き選択など、`renderContents()` を通らない描画経路は横組みのままです
- **配信フォントには矢印・幾何学図形・星・単位記号・囲み数字・罫線素片が入っていません。** 置換字形（◆）になります。詳細と対処は [日本語フォントで出せる文字と、変換側での対応方針](../japanese-font-coverage.md) に

## 入れ方

> [!IMPORTANT]
> **アプリ領域は2面あります。** どちらを起動するかは `otadata` が決めます。SDカードや OTA で更新した端末は `app1` から起動していることがあり、その状態で `0x10000`（app0）へ書いても**画面は何も変わりません**。両面へ書けば、どちらが選ばれても新しいファームが起動します。

```
py -m esptool --chip esp32s3 --port COM8 --baud 921600 write-flash 0x10000 CrossDiTo-x4-pro-v1.5.1.12.bin 0x7f0000 CrossDiTo-x4-pro-v1.5.1.12.bin
```

`Hash of data verified.` が2回出ることを確認してください。

**1.5.1.9 からは OTA で上げないでください。** 1.5.1.9 以前の OTA でこの版を書き込むこと自体はできますが、ブートループに入った端末からの復旧も含め、USB か SD カードのほうが確実です。SDカード経由なら、`.bin` を SD に置いて 設定 → 本体 → SD Card Firmware Update から選びます。

書き込む前にハッシュを照合してください。

```
certutil -hashfile CrossDiTo-x4-pro-v1.5.1.12.bin SHA256
```

### 起動しなくなったら

**電源ボタン＋下ボタンを押しながら起動**すると、SDカードからのファーム更新画面だけが立ち上がります。正常な `.bin` を SD に置いておけばここから戻せます。

ただし**ブートループに入っている場合はこの経路も使えません**（判定がアプリの中にあり、そこへ到達する前に落ちるため）。その場合は USB から書き込んでください。

## 使い方

1. 設定 → フォントを管理 から `BIZUDGothic` などをダウンロードする（Wi-Fi 接続が必要）
2. 本文フォントにそのフォントを選ぶ
3. 設定 → 言語 で「日本語」を選ぶ。ここで縦書きにするか尋ねられます
4. あとから変えるなら 設定 → 読書 → ページレイアウト → 組み方向

記号が ◆ になるのが気になる場合は、自分で `.cpfont` を焼けば出せます。手順は [フォント生成CLIの仕様](../prompts/build-jp-font-cli.md) に、実際に通したコマンドごと書いてあります。

## 扱わないもの

青空文庫連携と TXT から EPUB への変換は、このファームウェアでは扱いません。読むものの用意は母艦側の仕事として切り分けています。

なろう・カクヨムの作品を Xteink 向けの EPUB / XTC へ変換するものとして [NovelToXteink](https://github.com/simeon052/NovelToXteink) があります。
