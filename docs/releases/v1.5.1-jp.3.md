# CrossDiTo 1.5.1-jp.3

CrossDiTo_jp は [CrossDiTo 1.5.1](https://github.com/dito94/CrossDiTo) に日本語の読書環境を足した個人用のフォークです。CrossDiTo 1.5.1 そのものが [CrossInk 1.5.0](https://github.com/uxjulia/CrossInk) から作られた Xteink X4 Pro 向けのテストビルドで、さらにその元は [CrossPoint Reader](https://github.com/crosspoint-reader/crosspoint-reader) です。基盤のファームウェアと、そこから受け継いだ機能の功績はすべて上流の貢献者にあります。以下に挙げるのは、CrossDiTo 1.5.1 の上に足した変更だけです。

> [!IMPORTANT]
> **jp.1 / jp.2 は使わないでください。** UC8279 パネルを積んだ個体では画面が左右の鏡像になり、起動画面から先へ進みません。この版でその原因を直しています。

## ファイル

- ファイル: `CrossDiTo-x4-pro-v1.5.1-jp.3.bin`
- サイズ: 5,800,112 バイト
- SHA-256: `40e4c0aec2e8a688f1a1795464bf392a627fcce233ffd4518b0a6140716acce9`
- 対象コミット: `d215bc1`（main）

書き込む前に照合してください。手順は下記「入れ方」に。

## jp.2 からの変更

**表示が実機で動くようになりました。** これが jp.3 の唯一かつ最大の変更です。

### 症状

Xteink X4 Pro（起動時のプローブで **UC8279 / LUT_VER=0x68** と判定される個体）で、

1. 画面全体が左右の鏡像（鏡文字）になる
2. 起動画面から先へ画面が変わらない

2 について、端末自体は正常でした。シリアルログではホーム画面にもファイル一覧にも遷移し、入力にも反応しています。**最初の全面更新（起動画面）だけが画面に出て、以降の高速更新が像を作っていませんでした。**

### 原因

取り込んでいた freeink-sdk が古いものでした。上流 HEAD から**約1か月・100コミット**遅れており、次の修正が入っていませんでした。

```
3d90c8a 2026-08-20  Fix UC8279X4 display orientation to match hardware
ffeaaa2 2026-08-20  Fix UC8279 grayscale plane inversion bug
df4a1b7 2026-08-25  Fix ghosting by forcing power-off after AA refresh
11e7ad2 2026-08-27  Improve e-ink display initialization and ghosting
13d23ba 2026-08-29  Update X4 Pro display driver
39606d5 2026-09-09  Fix e-ink display buffer tracking and optimize SPI writes
4a69a29 2026-09-09  feat: accept absolute planes on UltraChip X4s
```

症状1は行送り順が逆だったため。症状2はそれとは独立した、高速更新（差分）側の問題でした。

### 変更内容

`freeink-sdk/libs/display` のみを上流 HEAD（`9f4d3f9`）に差し替えました。

SDK 全体ではなく表示ライブラリに絞ったのは、CrossDiTo が SDK に独自パッチを当てた状態で取り込んでいるためです（`InputManager::nextServiceDelayMs` は `dito94/CrossDiTo` にしか存在せず、上流にはありません）。全体を差し替えるとそれが落ちてビルドが壊れます。

上流の表示ライブラリが参照するボード定義のうち、こちらが取り込んでいない3つ（`isOnePage` / `isX4Classic` / `Board::WsEpaper397`）には互換用の措置を入れています。いずれも他機種向けの分岐で、この機の動作には影響しません。

## フォントの入手経路を直しました

実機でフォントのダウンロードが **Invalid font manifest** で失敗していました。

CrossInk 系のファームは各ファイルに `crc32` を必須とします（ダウンロード破損の検知に使う）。
指していた crosspoint-jp のマニフェストにはこれが1つも無く、弾かれていました。
どちらも `"version": 1` を名乗るため版番号では判別できません。形式が2系統に分かれています。

CrossInk 本来の配信元には日本語フォントが1つもありません（24系統すべてラテン系）。
そのため**フォント本体は引き続き crosspoint-jp から取り、マニフェストだけをこちらで持つ**
形にしました。`baseUrl` はあちらを指したままで、各ファイルの `crc32` を計算して補っています。

フォント本体を再配布しないので、OFL のライセンス同梱義務は生じません。

マニフェスト: https://github.com/simeon052/CrossDiTo_jp/releases/tag/sd-fonts-jp

> [!NOTE]
> crosspoint-jp が資産を差し替えると `crc32` が合わなくなり、ダウンロードが失敗するように
> なります。マニフェストを作り直せば復旧しますが、自動では追随しません。

## OTA の参照先を変えました

これまで上流の `uxjulia/CrossInk` を指していました。**そのまま更新すると日本語化も
X4 Pro の表示修正も上書きされます。** このフォークのリリースへ向けました。

ただし OTA はまだ機能しません。既知の問題が2つ残っています。

1. `/releases/latest` はプレリリースを除外します。このリポジトリのリリースはすべて
   プレリリースなので 404 になり、「更新なし」として扱われます
2. 版の比較器が `1.5.1-jp.3` の `-jp.3` を読み飛ばし `[1,5,1,0]` と解釈します。
   jp 版どうしの新旧を区別できません

いまは「更新なし」として振る舞います。上流を引いてくる危険がなくなった点が今回の成果です。
実用にするには版表記の見直し（比較器は4桁対応なので `1.5.1.3` 形式なら機能します）と、
検証済みリリースの通常公開が要ります。

|---|---|

縦組みの組版は「幅と高さを入れ替えた紙面」で横組みとして行い、配置の瞬間に画面座標へ戻しています。既存のレイアウトエンジンに手を入れずに済ませるための方式です。この方式のおかげで、横組みで「字の上」に取るものが列の右、「字の下」に引くものが列の左に来るため、ルビと傍線の位置は座標を写すだけで日本語の慣習に一致しました。

実装の詳細は [docs/japanese.md](../japanese.md) を参照してください。

## 入れ方

書き込むのはアプリケーションイメージだけです。ブートローダとパーティションテーブルは含みません。

### 書き込む前に: フラッシュ全体をバックアップ

**純正ファームから初めて入れる場合は必須です。** 純正のパーティション配置がこのファームと同じである保証はなく、アプリ領域だけ差し替えて起動しない可能性があります。

```
py -m esptool --chip esp32s3 --port COM8 read-flash 0 0x1000000 stock-x4pro-backup.bin
```

戻すときは `write-flash 0 stock-x4pro-backup.bin` です。

> [!NOTE]
> コマンド名は esptool v5 でハイフン区切りになりました（`read_flash` → `read-flash`、
> `write_flash` → `write-flash`）。v4 以前を使っている場合はアンダースコアのままです。

### 方法A: SDカード経由

すでに CrossDiTo / CrossInk が入っている端末向けで、USB を使わないぶん安全です。

1. `.bin` を SDカードの任意の場所へ置く
2. 設定 → システム → SD Card Firmware Update から選んで確定

### 方法B: USB（esptool）

```
py -m pip install esptool
py -m esptool --chip esp32s3 --port COM8 --before usb-reset write-flash 0x10000 CrossDiTo-x4-pro-v1.5.1-jp.3.bin
```

`0x10000` は `partitions.csv` の `app0` の先頭です。ポート番号は実際の値に置き換えてください。

**接続できないとき** — `No serial data received` が出る場合は、端末がダウンロードモードに入っていません。電源を入れ直した直後に実行するか、**上ボタン（GPIO0）を押しながら電源を入れて**から `--before no-reset` で書き込んでください。

### 起動しなくなったら

**電源ボタン＋下ボタンを押しながら起動**すると、SDカードからのファーム更新画面だけが立ち上がります。正常な `.bin` を SD に置いておけばここから戻せます。X4 Pro が下ボタンを使うのは、上ボタンが GPIO0（ESP32-S3 のストラップピン）で起動時に誤検出しうるためです。

### 書き込む前にハッシュを照合する

```
certutil -hashfile CrossDiTo-x4-pro-v1.5.1-jp.3.bin SHA256
```

## 使い方

1. 設定 → フォントを管理 から `BIZUDGothic` などをダウンロードする（Wi-Fi 接続が必要）
2. 本文フォントにそのフォントを選ぶ（UIの日本語もこのフォントから出ます）
3. 設定 → 言語 で「日本語」を選ぶ
4. 縦組みにするなら 設定 → 読書 → 組み方向 を「縦書き」にする

**フロントライトは画面上端から下へスワイプ**で開きます（明るさ・色温度・オンオフ）。設定画面には出していません。点灯スケジュールだけは 設定 → 表示 にあります。X4 Pro ではリーダーのメニューが下端からのスワイプに移されています。

## 既知の制限

- 画像や表を含む本は縦組みで崩れます。組版を「幅と高さを入れ替えた紙面」で行っているためで、受け入れた判断です。設定画面にも注記があります。
- バイオニックリーディングは縦組みでは無効です。組版が語を「太字の頭」と「残り」に割って測り、その合計で語の位置を決めるので、欧文を寝かせて描く縦組みでは位置がずれます。
- 背景反転は縦組みでも出ませんが、これは横組みでも同じです。実文字への `background-color` はもともと描かれません。
- 脚注プレビューや抜き書き選択など、`renderContents()` を通らない描画経路は横組みのままです。
- 行間を詰めすぎると列が重なります。ただし同じ値では横組みでも行が重なるので、縦組み固有の破綻ではありません。実用域は 100% 以上です。
- 日本語フォントの配信は [zrn-ns/crosspoint-jp](https://github.com/zrn-ns/crosspoint-jp) のリリース資産に依存しています。常用するなら自前にミラーしてください。
- 日付書式のサンプル表示は英語のままです。実際の描画も英語の月名を出すため、ラベルだけ和訳すると表示と食い違います。

## 扱わないもの

青空文庫連携と TXT→EPUB 変換は、このファームウェアでは扱いません。端末側に持たせると、ネットワーク・スクレイピング・文字コード変換・組版前処理が読書アプリの中に混ざります。読むものの用意は母艦側の仕事として切り分けています。

なろう・カクヨムの作品を Xteink 向けの EPUB / XTC へ変換するものとして [NovelToXteink](https://github.com/simeon052/NovelToXteink) があります。
