# CrossDiTo 1.5.1-jp.4

CrossDiTo_jp は [CrossDiTo 1.5.1](https://github.com/dito94/CrossDiTo) に日本語の読書環境を足した個人用のフォークです。CrossDiTo 1.5.1 そのものが [CrossInk 1.5.0](https://github.com/uxjulia/CrossInk) から作られた Xteink X4 Pro 向けのテストビルドで、さらにその元は [CrossPoint Reader](https://github.com/crosspoint-reader/crosspoint-reader) です。基盤のファームウェアと、そこから受け継いだ機能の功績はすべて上流の貢献者にあります。以下に挙げるのは、CrossDiTo 1.5.1 の上に足した変更だけです。

> [!IMPORTANT]
> **jp.1 / jp.2 は使わないでください。** UC8279 パネルを積んだ個体では画面が左右の鏡像になり、起動画面から先へ進みません。jp.3 でその原因を直しています。

## ファイル

- ファイル: `CrossDiTo-x4-pro-v1.5.1-jp.4.bin`
- サイズ: SIZE_PLACEHOLDER バイト
- SHA-256: `SHA_PLACEHOLDER`
- 対象コミット: `COMMIT_PLACEHOLDER`（main）

書き込む前に照合してください。手順は下記「入れ方」に。

## jp.3 からの変更

**日本語の縦書きが実機で使えるようになりました。** jp.3 では、そもそも縦書きに切り替える手段が画面上に存在していませんでした。

### 縦書きの設定が設定画面に出ていなかった

組み方向と縦書きの字間の設定を、**実際には使われていない一覧**に入れていました。設定画面を組み立てているのは別の関数で、そちらには入っていませんでした。シミュレータは設定ファイルを直接書いて起動するため、この経路を一度も通っておらず、最後まで気づけませんでした。

生きている一覧へ移しました。**設定 → 読書 → ページレイアウト** に「組み方向」と「縦書きの字間」が出ます。

### 縦組みの欧文が読めなかった

「100点満点中」が「001点満点中」のように見え、しかも字が寝る向きも逆でした。

描画に使っていた `drawTextRotated90CW()` が、名前に反して**反時計回り**に描いていたためです。字形の x 軸が画面の上方向へ写り、送りも上へ進むので、語が下から上へ並びます。この向きは X3 の側面ボタンのラベルにとっては正しいので、関数自体は変えていません。呼ぶ側が間違っていました。

日本語の縦組みで欧文に必要なのは時計回り・上から下（CSS の `text-orientation: sideways`）です。`drawTextSideways()` を足して、縦組みからはそちらを使うようにしました。送り・カーニング・合字・結合文字・合成字形は両方向で共有しているので、片方だけ直って食い違うことはありません。

### 一度豆腐になると再起動まで戻らなかった

ファイル転送メニューなど、ネットワークを使う画面を開くと UI の日本語が全部豆腐（◆）になり、メインメニューへ戻っても直りませんでした。

ネットワーク動作の前にフォントを解放する処理が、UI の CJK フォールバックまで落としていました。復旧は各呼び出し側に任されていて、抜けがありました。画面遷移のたびに拾い直すようにしています。

### ステータスバーが豆腐になることがあった

UI のフォールバック登録が、要求する大きさちょうどの `.cpfont` を要求していました。8pt を持たないフォントでは登録に失敗し、下部のタイトルが豆腐になります。近い大きさで代用するようにしました。

### そのほか

| 内容 | 影響 |
|---|---|
| 設定 → 言語 で日本語を選んだとき、組み方向がまだ横書きなら縦書きに切り替えるかを一度だけ尋ねる | 黙っては切り替えません（後述） |
| 「読書方向」を「画面の向き」に | 画面の回転を指す設定で、組み方向とは別のものです |
| ソースに NUL バイトが直書きされていた（Copilot 指摘） | NUL を終端とみなすツールがファイルを途中で切りうる |
| ビルドのバージョン文字列にコミットを載せた | CI は detached HEAD でチェックアウトするので、どのコミットをビルドしても同じ文字列になり、起動画面から端末のイメージを特定できませんでした |

### 日本語を選んだときの確認について

言語を日本語にした瞬間だけ、縦書きにするかを一度尋ねます。黙って切り替えないのは、EPUB の `writing-mode` を読んで自動判定しないのと同じ理由です。組み方向が本や言語の都合で入れ替わると、同じ設定なのに挙動が変わる理由が読者から見えなくなります。確認を挟めば、組み方向は読者が選んだものであり続けます。

日本語から他の言語へ変えても、横書きに戻すことはしません。縦書きで欧文を読む選択は読者のものです。

## jp.3 の記述の訂正

jp.3 のリリースノートに「**X4 Pro のフロントライトが深いスリープから復帰しない問題（上流 2026-08-28〜29 に5件）**が未取り込み」と書きましたが、これは誤りでした。

該当する時期の上流コミットを1件ずつ当たった結果は次のとおりです。

| 上流コミット | この端末への効果 |
|---|---|
| `f0c65506` バッテリ駆動時のラッチ保持 | **既に入っています** |
| `cdd89b1d` 電源ボタンの検出と待ち時間 | **既に入っています** |
| `e37164ca` コールドブートの誤判定 | X4 Pro では実質無効化。判定結果は今と同じ |
| `4a679d5d` SD停止・シングルクリック起動 | こちらの実装のほうが先に進んでいます。上流は設定を読むまで判断を遅らせますが、このフォークは起動直後に NVS のミラーから読んで判定します。SD もレールごと切ってスリープ中も保持しています |
| `9ba16086` 短押しの取りこぼし | 同じく解決済み。上流はポーリング間隔を刻む対症療法ですが、こちらはボタンとタッチの割り込みがループを即座に起こします |

フロントライト自体も上流から遅れていません。実装が分かれているだけです。**復帰時の点灯は設定 → 表示 →「復帰時にライトを元に戻す」で制御できます。** これが OFF だと、スリープ前に点いていても復帰時は消えたままになります。フロントライトのスケジュールを設定している場合はそちらが優先されます。

実装の詳細は [docs/japanese.md](../japanese.md) を参照してください。

## 入れ方

書き込むのはアプリケーションイメージだけです。ブートローダとパーティションテーブルは含みません。

### 書き込む前に: フラッシュ全体をバックアップ

**純正ファームから初めて入れる場合は必須です。** 純正のパーティション配置がこのファームと同じである保証はなく、アプリ領域だけ差し替えて起動しない可能性があります。

```
py -m esptool --chip esp32s3 --port COM8 read-flash 0 0x1000000 stock-x4pro-backup.bin
```

戻すときは `write-flash 0 stock-x4pro-backup.bin` です。

> [!NOTE]
> コマンド名は esptool v5 でハイフン区切りになりました（`read_flash` から `read-flash`、
> `write_flash` から `write-flash`）。v4 以前を使っている場合はアンダースコアのままです。

### 方法A: SDカード経由

すでに CrossDiTo / CrossInk が入っている端末向けで、USB を使わないぶん安全です。

1. `.bin` を SDカードの任意の場所へ置く
2. 設定 → システム → SD Card Firmware Update から選んで確定

### 方法B: USB（esptool）

> [!IMPORTANT]
> **アプリ領域は2面あります。** どちらを起動するかは `otadata` が決めます。SDカードや OTA で更新した端末は `app1` から起動していることがあり、その状態で `0x10000`（app0）へ書いても**画面は何も変わりません**。jp.3 から jp.4 の検証中、実際にこれで数往復しました。
>
> 両面へ書けば、どちらが選ばれても新しいファームが起動します。

```
py -m pip install esptool
py -m esptool --chip esp32s3 --port COM8 --baud 921600 write-flash 0x10000 CrossDiTo-x4-pro-v1.5.1-jp.4.bin 0x7f0000 CrossDiTo-x4-pro-v1.5.1-jp.4.bin
```

`0x10000` が app0、`0x7f0000` が app1 です。**この配置は純正のパーティション表のもので、リポジトリの `partitions.csv`（app1 を `0x650000` に置く）とは違います。** パーティション表は焼いていないので、端末が使うのは純正のものです。手元の個体で確かめるには次を読み出してください。

```
py -m esptool --chip esp32s3 --port COM8 read-flash 0x8000 0x1000 parttable.bin
py -m esptool --chip esp32s3 --port COM8 read-flash 0xe000 0x2000 otadata.bin
```

`otadata` は 0x1000 ごとに2つの枠があり、先頭4バイトの `ota_seq` が大きいほうが勝ちます。`(ota_seq - 1) % 2` が起動するアプリ面の番号です。

**接続できないとき** — `No serial data received` が出る場合は、端末がダウンロードモードに入っていません。電源を入れ直した直後に実行するか、**上ボタン（GPIO0）を押しながら電源を入れて**から `--before no-reset` で書き込んでください。

### 起動しなくなったら

**電源ボタン＋下ボタンを押しながら起動**すると、SDカードからのファーム更新画面だけが立ち上がります。正常な `.bin` を SD に置いておけばここから戻せます。X4 Pro が下ボタンを使うのは、上ボタンが GPIO0（ESP32-S3 のストラップピン）で起動時に誤検出しうるためです。

### 書き込む前にハッシュを照合する

```
certutil -hashfile CrossDiTo-x4-pro-v1.5.1-jp.4.bin SHA256
```

## 使い方

1. 設定 → フォントを管理 から `BIZUDGothic` などをダウンロードする（Wi-Fi 接続が必要）
2. 本文フォントにそのフォントを選ぶ（UIの日本語もこのフォントから出ます）
3. 設定 → 言語 で「日本語」を選ぶ。ここで縦書きにするか尋ねられます
4. あとから変えるなら 設定 → 読書 → ページレイアウト → 組み方向

**フロントライトは画面上端から下へスワイプ**で開きます（明るさ・色温度・オンオフ）。設定画面には出していません。点灯スケジュールと「復帰時にライトを元に戻す」は 設定 → 表示 にあります。X4 Pro ではリーダーのメニューが下端からのスワイプに移されています。

## 既知の制限

- 画像や表を含む本は縦組みで崩れます。組版を「幅と高さを入れ替えた紙面」で行っているためで、受け入れた判断です。設定画面にも注記があります。
- **バイオニックリーディングは縦組みでは無効です。** 太字にする範囲を語頭から43%で決める仕組みで、分かち書きをしない日本語では「1文字の語が全部太字」か「形態素の途中で切れる」かのどちらかにしかなりません。空白で区切られた語の頭が手がかりになるという前提が、日本語では成り立ちません。
- 背景反転は縦組みでも出ませんが、これは横組みでも同じです。実文字への `background-color` はもともと描かれません。
- 脚注プレビューや抜き書き選択など、`renderContents()` を通らない描画経路は横組みのままです。
- 行間を詰めすぎると列が重なります。ただし同じ値では横組みでも行が重なるので、縦組み固有の破綻ではありません。実用域は 100% 以上です。
- 日本語フォントの配信は [zrn-ns/crosspoint-jp](https://github.com/zrn-ns/crosspoint-jp) のリリース資産に依存しています。あちらが資産を差し替えると `crc32` が合わなくなり、ダウンロードが失敗します。常用するなら自前にミラーしてください。
- 日付書式のサンプル表示は英語のままです。実際の描画も英語の月名を出すため、ラベルだけ和訳すると表示と食い違います。

### OTA はまだ機能しません

参照先はこのフォークへ向けてあるので、更新しても日本語化や表示修正が上書きされる危険はありません。ただし次の2点で「更新なし」として振る舞います。

1. `/releases/latest` はプレリリースを除外します。このリポジトリのリリースはすべてプレリリースなので 404 になります
2. 版の比較器が `1.5.1-jp.4` の `-jp.4` を読み飛ばし `[1,5,1,0]` と解釈します。jp 版どうしの新旧を区別できません

実用にするには版表記の見直し（比較器は4桁対応なので `1.5.1.4` 形式なら機能します）と、検証済みリリースの通常公開が要ります。

## 扱わないもの

青空文庫連携と TXT から EPUB への変換は、このファームウェアでは扱いません。端末側に持たせると、ネットワーク・スクレイピング・文字コード変換・組版前処理が読書アプリの中に混ざります。読むものの用意は母艦側の仕事として切り分けています。

なろう・カクヨムの作品を Xteink 向けの EPUB / XTC へ変換するものとして [NovelToXteink](https://github.com/simeon052/NovelToXteink) があります。
