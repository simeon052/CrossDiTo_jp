# プロンプト: 日本語フォント生成 CLI を作る

このファイルはコーディングエージェントに渡す仕様書です。そのまま貼って使えます。

---

## 作るもの

手元の TTF/OTF から、Xteink X4 Pro（CrossDiTo_jp ファーム）向けの `.cpfont`
ファイル一式を作る CLI ツール。記号の収録範囲を広げて、配信版のフォントで
置換字形（◆）になっていた矢印・幾何学図形・星・単位記号を出せるようにする。

## 最重要の制約

**フォント本体を同梱・ダウンロードしないこと。** 利用者が自分で用意した
TTF/OTF のパスを必ず引数で受け取る。ツールのリポジトリにフォントを置いたり、
URL から取りに行く機能を作ったりしてはいけない。再配布には許諾が要るため、
「作る機能」だけを提供する。生成物も利用者の手元に留まる前提とする。

## 既存資産を使う

`.cpfont` の書き出しを自前で実装しないこと。**`zrn-ns/crosspoint-jp` の
`lib/EpdFont/scripts/fontconvert_sdcard.py` を呼び出すラッパーとして作る。**

理由: この形式は縦組み用の字形（OpenType の `vert` フィーチャから抽出した
置換字形）を含む v5 で、括弧・ダッシュ・長音符が縦組みで正しい向きになるのは
これがあるため。

**`simeon052/CrossDiTo_jp` 側にある同名スクリプトを使ってはいけない。** あちらは
v4 を書き出し、vert 字形を持たない。使うと縦組みの見た目が落ちる。

ツールは crosspoint-jp のチェックアウト先をパスで受け取る（`--converter-repo`）か、
スクリプトのパスを直接受け取る。見つからなければ明示的に失敗すること。

## 収録範囲の決め方（ここが本題）

`fontconvert_sdcard.py` は次の2つを受け取り、**両方に入っている文字だけ**を
収録する（積集合）。

- `--intervals`: プリセット名のカンマ区切り。生の範囲は渡せない
- `--codepoints-file`: 16進コードポイントを1行1つ書いたファイル

配信版は `intervals: ascii,latin1,punctuation,cjk` と
`codepoints/japanese_jis0213.txt` の積集合で、実際に出せるのは 13,474 字。
記号がごっそり抜けている（U+2100-U+27BF が0字）。

**このツールは積集合の罠を避けるため、収録したい文字を1つの
コードポイントファイルに全部書き出し、intervals 側はそれを覆う十分広い
プリセットを渡す方式にすること。** intervals で削られて意図した字が落ちる、
という事故を構造的に防ぐ。プリセットが足りなければ
`fontconvert_sdcard.py` の `INTERVAL_PRESETS` に追加する手順を README に書く
（スクリプトを書き換えずに済むなら、そのほうがよい）。

### 既定の収録範囲

配信版の 13,474 字に、次を足したものを既定とする。

| ブロック | 範囲 | 中身 |
|---|---|---|
| 文字様記号 | U+2100-214F | ℃ ℉ № |
| 矢印 | U+2190-21FF | → ← ↑ ↓ ⇒ |
| 数学記号 | U+2200-22FF | ∀ ∞ ≠ ≦ |
| 囲み英数字 | U+2460-24FF | ① ② ③ |
| 罫線素片 | U+2500-257F | ─ │ ┌ |
| 幾何学模様 | U+25A0-25FF | ■ □ ● ○ ◆ ◇ ▲ |
| その他の記号 | U+2600-26FF | ★ ☆ ♪ ♂ ♀ |

配信版の一覧は `CrossDiTo_jp/docs/japanese-font-coverage.txt` に範囲形式で
置いてある。これを読み込んで土台にするとよい。

`--coverage` で切り替えられるようにする。最低限 `default`（上記）と
`stock`（配信版と同じ）と、任意のファイルを指すパス指定。

## 引数

| 引数 | 必須 | 内容 |
|---|---|---|
| `--regular PATH` | ○ | レギュラーの TTF/OTF |
| `--bold PATH` | | ボールド |
| `--italic PATH` | | イタリック |
| `--bolditalic PATH` | | ボールドイタリック |
| `--family NAME` | ○ | 端末の設定画面に出る名前。英数字とハイフンのみ |
| `--sizes LIST` | | 既定 `8,10,12,14,16,18`。8/10/12 はUIのフォールバックに使われるので、外すと設定画面の日本語が豆腐になる |
| `--coverage SPEC` | | `default` / `stock` / ファイルパス |
| `--converter-repo PATH` | ○ | crosspoint-jp のチェックアウト先 |
| `--out DIR` | | 既定 `./out` |

## 出力

そのまま SDカードにコピーできる形にする。

```
<out>/<Family>/<Family>_8.cpfont
<out>/<Family>/<Family>_10.cpfont
...
```

端末は SDカードの `/fonts/<Family>/` と `/.fonts/<Family>/` を見る。
ディレクトリ名が設定画面に出る名前になる。ファイル名は
`<なんでも>_<サイズ>.cpfont` であればよい。

## 検証と報告

生成後に次を必ず出すこと。**黙って通さない。**

1. サイズごとの収録字数
2. **要求したのに元の TTF に無かった文字の一覧**（コードポイントと文字）。
   収録リストに載っていても元フォントに字が無ければ空の字形になり、端末では
   空白として出る。◆ より気づきにくいので、ここは必ず報告する
3. vert 字形が何字ぶん取れたか。0 だった場合は**警告を出す**。縦組みで
   括弧やダッシュが正しい向きにならない状態を意味する
4. 各ファイルのサイズと SHA-256

## 非目標

- フォントの同梱・ダウンロード
- 生成したフォントの配布・アップロード機能
- 端末への転送（SDカードへのコピーは利用者が手でやる）
- `.cpfont` 形式の再実装

## 実地で確認済みの手順と落とし穴

この仕様は机上のものではなく、BIZ UDGothic の TTF で実際に通してある。

### 通した手順

1. `INTERVAL_PRESETS` に記号用プリセットを足す（`--intervals` はプリセット名しか
   受け付けないため、生の範囲は渡せない）

```python
"jp-symbols":  [(0x2100, 0x214F), (0x2190, 0x21FF), (0x2200, 0x22FF),
                (0x2460, 0x24FF), (0x2500, 0x257F), (0x25A0, 0x25FF),
                (0x2600, 0x26FF)],
```

2. コードポイントファイルを `japanese_jis0213` ∪ 記号（**元フォントが実際に
   持つものだけ**）で作る
3. 焼く

```
python fontconvert_sdcard.py --regular BIZUDGothic-Regular.ttf --bold BIZUDGothic-Bold.ttf --name BIZUDGothic-Ext --sizes 8,10,12,14,16,18 --intervals ascii,latin1,punctuation,cjk,jp-symbols --codepoints-file codepoints_jp_ext.txt --output-dir out/BIZUDGothic-Ext
```

### 結果

| | 字形数 | 区間数 | 14pt のサイズ |
|---|---|---|---|
| 配信版と同じ設定 | 19,522 | 201 | 2,285,885 B |
| 記号を足した版 | 19,903 | 237 | 2,334,331 B |

全6サイズ（レギュラー＋ボールド）で 25.15 MB。すべて v5、vert 字形 34 個。

### 落とし穴

**コードポイントファイルの文字コード。** `fontconvert_sdcard.py` は `open()` に
エンコーディングを渡していないため、日本語 Windows では cp932 として読もうとして
落ちる。

```
UnicodeDecodeError: 'cp932' codec can't decode byte 0x83
```

配布されている `japanese_jis0213.txt` は冒頭に日本語のコメントがあるので、
**そのままでは Windows で使えない**（CI は Linux なので通る）。ツールが生成する
コードポイントファイルは**コメントも含めて ASCII だけにする**か、変換器の呼び出し前に
`encoding='utf-8'` を渡すよう修正すること。

**元フォントに無い字は空白になる。** BIZ UDGothic の実測では、配信版の収録リスト
13,474 字のうち **3,227 字が元フォントに存在しない**。これらは ◆ ではなく空白として
出るので、◆ より気づきにくい。報告を必須にしているのはこのため。

**記号は 1,088 字を要求して 294 字しか増えない。** 残りは元フォントに無い。
これで十分で、それ以上は存在しない。

## 動作確認

- `--coverage stock` で作ったものが、配信版と同じ字数（13,474）になること
- `--coverage default` で `→`（U+2192）と `★`（U+2605）が収録されること
- 生成物を SDカードに置いて、端末の 設定 → 本文フォント に `--family` の名前が
  出ること
- 縦組みで `〈〉` `——` `〜` が正しい向きになること（vert 字形が効いている確認）
