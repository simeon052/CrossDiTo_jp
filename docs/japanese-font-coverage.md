# 日本語フォントで出せる文字と、変換側での対応方針

CrossDiTo_jp が配信している日本語フォントには、**JIS X 0208 の1区・2区にある記号がまったく入っていません**。矢印・幾何学図形・星・音符・単位記号が出ず、置換字形（◆）になります。

端末側で直せる問題ではないため、EPUB へ変換する段階で吸収します。この文書はその方針と、変換側が使う収録文字一覧の仕様です。

## 何が出て、何が出ないか

配信しているのは BIZUDGothic / BIZUDMincho / NotoSansJp / NotoSerifJp の4種で、**4種とも収録文字は同じ**です。[zrn-ns/crosspoint-jp](https://github.com/zrn-ns/crosspoint-jp) の `lib/EpdFont/scripts/sd-fonts.yaml` が次のように定義しています。

```
intervals: ascii,latin1,punctuation,cjk
codepoints_file: codepoints/japanese_jis0213.txt
```

`--codepoints-file` は **intervals との積集合**です（「only codepoints present in both the intervals and this file are included」）。

| | 文字数 |
|---|---|
| intervals の合計 | 22,336 |
| 収録リストの合計 | 13,957 |
| **実際に出せる字** | **13,474** |

リストに載っているのに intervals で落ちた 483 字は、CJK拡張Aの漢字（U+3400-U+4DBF）とカタカナ拡張（U+31F0-U+31FF）でした。記号は**そもそもリストに載っていません**。

ブロック別の収録状況:

| ブロック | 収録 / 全体 |
|---|---|
| ASCII | 95 / 95 |
| Latin-1 補助 | 96 / 96 |
| 一般句読点 (U+2000-206F) | 112 / 112 |
| CJK記号と句読点 | 64 / 64 |
| ひらがな / カタカナ | 96 / 96 |
| CJK統合漢字 | 12,560 / 20,992 |
| 半角・全角形 | 240 / 240 |
| **文字様記号 (U+2100-214F)** | **0 / 80** |
| **矢印 (U+2190-21FF)** | **0 / 112** |
| **数学記号 (U+2200-22FF)** | **0 / 256** |
| **囲み英数字 (U+2460-24FF)** | **0 / 160** |
| **罫線素片 (U+2500-257F)** | **0 / 128** |
| **幾何学模様 (U+25A0-25FF)** | **0 / 96** |
| **その他の記号 (U+2600-26FF)** | **0 / 256** |

一般句読点が全部入っているので、`※` `…` `‥` `—` `―` は出ます。ここを取り違えないでください。

## 収録文字一覧

[`japanese-font-coverage.txt`](./japanese-font-coverage.txt) に範囲形式で置いてあります。4,105範囲・13,474字。

```
0020-007E
00A0-00FF
2010-2027
...
```

`START-END`（16進、両端を含む）。単一文字は `START` のみ。`#` で始まる行はコメント。

変換側はこれを読み込んで集合を作り、出力する全文字が集合に入っているかを検査します。

## 変換側の方針

### 1. 置換する（意味が保てるもの）

| 元 | 置換先 | 備考 |
|---|---|---|
| `→` `⇒` `⇨` | `－＞` | 全角なので縦組みで正しく回る。`->` は半角2文字ぶん寝るので避ける |
| `←` `⇐` | `＜－` | |
| `↑` `↓` | `上` `下`、または文脈に応じて削除 | 記号として意味を持つ場合のみ |
| `≪` `≫` | `《` `》` | 見た目がほぼ同じで、こちらは出せる |
| `①`〜`⑳` | `（１）`〜`（２０）` | 全角括弧＋全角数字 |
| `℃` | `°Ｃ` | `°` は Latin-1 で出せる |
| `✕` `✗` | `×` | Latin-1 の乗算記号 |
| `★` `☆` | `＊` | |
| `■` `□` `●` `○` `◆` `◇` `▲` `△` | `＊`、または後述の区切り扱い | |
| `─` `━` `│` | `―`（U+2015） | 一般句読点なので出せる |
| `♪` `♫` | 削除 | 置換先が無い。残すと ◆ になる |

置換は**元のテキストを書き換える**ので、変換ログに「どの文字を何に置換したか」を必ず残してください。読者が原文と突き合わせられなくなるのが一番まずい失敗です。

### 2. 区切り記号は `<hr>` に寄せる

web小説では `◇◇◇` `◆◆◆` `＊＊＊` `※※※` が場面転換の区切りとして頻出します。これらだけからなる段落は、**記号を置換するのではなく `<hr>` に変換する**のが素直です。

- 端末は `<hr>` を罫線として描きます。縦組みでは縦罫になります（[PR #11](https://github.com/simeon052/CrossDiTo_jp/pull/11) で対応）
- 出せない記号の問題が消える
- 場面転換という**意味**が保たれる

判定は「記号と空白だけからなる段落で、記号が3文字以上」程度で十分です。`＊＊＊` のように出せる記号の場合も、`<hr>` にしたほうが見栄えは揃います。

### 3. 検査して報告する（置換しないもの）

置換表にない未収録文字は、**黙って落とさずに変換ログへ出してください**。

- どのファイルの何行目か
- コードポイントと文字
- 前後の文脈を数文字

記号は種類が多く、置換表を先回りで完備するのは無理です。実際に出てきたものを見てから表を足すほうが確実です。検査を入れておけば、端末で ◆ を見つけてから原因を探す往復が要りません。

## 一覧の再生成

配信元がフォントを更新すると収録範囲が変わります。そのときは次で作り直してください。

```bash
python - <<'PY'
intervals = [(0x0020,0x007E),(0x0080,0x00FF),(0x2000,0x206F),
             (0x3000,0x303F),(0x3040,0x309F),(0x30A0,0x30FF),
             (0x4E00,0x9FFF),(0xF900,0xFAFF),(0xFF00,0xFFEF),(0xFFFD,0xFFFD)]
allowed = set()
for a, b in intervals:
    allowed.update(range(a, b + 1))
listed = set()
for line in open('codepoints/japanese_jis0213.txt', encoding='utf-8'):
    line = line.strip()
    if line and not line.startswith('#'):
        listed.add(int(line, 16))
print(len(allowed & listed))
PY
```

`intervals` は `sd-fonts.yaml` の `intervals:` を `fontconvert_sdcard.py` の `INTERVAL_PRESETS` で展開したものです。両方が変わりうるので、更新時は両方を確認してください。

## 注意点

- **収録リストに載っていても、元の TTF にその字が無ければ出ません。** 一覧は「出せる可能性がある字」の上限です。BIZ UDGothic は JIS X 0208 を満たすので常用範囲では問題になりませんが、拡張漢字では差が出ることがあります
- **内蔵フォント（SDフォント未選択時）は収録範囲が違います。** 矢印 U+2190-21FF と数学記号 U+2200-22FF を持つ代わりに、漢字を持ちません。日本語を読むなら SDフォントを選ぶ前提です
- この問題は配信元の収録リスト生成の漏れです。リストは JIS X 0213 を名乗っていますが、実際は ASCII・Latin-1・一般句読点・CJK記号・かな・半角全角形と、Unihan の属性から拾った**漢字だけ**で、JIS の1区・2区にある非漢字の記号がどのブロックからも拾われていません。上流が直せば、この変換側の対応の大半は不要になります
